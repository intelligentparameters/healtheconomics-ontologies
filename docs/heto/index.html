Health Economics Task Ontology (HETO)

HETO, the Health Economics Task Ontology, describes recognisable units of health economics work, such as adding discounting to an economic model or running a probabilistic sensitivity analysis, and connects each one to the real things it works on, as RHEO and OHEO define them. A HETO task is a reusable specification of a defined unit of work. It states an intended result and the main actions directed towards it, independently of any particular practitioner, project or software. Following the Information Artifact Ontology, a task specification is a plan specification (IAO_0000104) with an objective specification and action specifications as parts. Each named task in the pilot catalogue is an individual with its own URI; subclasses of task specification classify kinds of task. A particular performance of the work is a separate planned process (health economics task performance), linked to the specification it follows by 'specified by information' (RO_0017010), as Duncan et al. 2024 recommend. Three relations are kept apart. Classification (rdf:type) says what kind of task something is; decomposition (has subtask specification) says which smaller tasks make up a larger one; ordering (normally precedes) says which work is usually done first. Policy (decided by Darrin Baines, 17 October 2026). HEO is a thesaurus of concepts, which are not real things; RHEO and OHEO define the real things of health economics within BFO 2020; HETO describes work on those real things, so its logical links go to RHEO and OHEO only. Each task names the RHEO or OHEO types of its inputs, outputs and processes, and the HETO role of the person who does it. HEO concepts are not linked from heto.ttl. They appear only in heto-mappings.sssom.tsv, as secondary skos:relatedMatch rows for learning and navigation, which state no requirement and no identity. No HETO class uses a HEO concept URI. Requirements on the catalogue and on records of task performances are SHACL shapes in heto-shapes.ttl.

health economics task performance

https://healtheconomics.wiki/ontologies/heto/HETO_0000030

A planned process in which one or more people carry out health economics work as a task specification in the HETO catalogue prescribes, whether or not the work achieves its objective.

Subclass of planned processexternal
Restrictions specified by informationexternal some task specification
contributor Michelle Ashleyexternal
definition source COB planned process (COB_0000082); Duncan et al. 2024
editor note A performance is linked to the task specification that prescribes it by 'specified by information' (RO_0017010). That link holds even when the work fails or departs from the specification, which is why HETO uses it rather than requiring a plan that concretizes the specification (Duncan et al. 2024). The kinds of process involved, such as a RHEO model run, are recorded on the task specification with 'has process type'.

editor note Each named task in the HETO catalogue is one individual of this class or of one of its subclasses, with its own URI. The specification is information. A particular practitioner doing the work is a separate process, a health economics task performance, linked to the specification by 'specified by information' (RO_0017010), as Duncan et al. 2024 propose for plan specifications. A calendar reminder, a topic heading or one person's to-do item is not by itself a task specification.
